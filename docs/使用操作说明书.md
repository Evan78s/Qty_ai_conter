## 1. 首次登录与改密

1. 浏览器打开 `https://你的域名`，自动进入登录页。
2. 输入**安装时设置的管理员账号和初始密码**（不是演示账号，是你自己在 `/setup` 里填的）。
3. 首次登录会**强制弹出「修改密码」窗口**：
   - 原密码：填初始密码
   - 新密码：至少 8 位，建议字母+数字+符号
   - 确认新密码：再输一遍
   - 点「确认修改」→ 系统自动退出 → 用新密码重新登录。

> 忘记密码？见文末[常见问题](#10-常见问题)。

## 2. 界面总览与门店切换

系统为连锁结构设计，**几乎所有数据都可以按门店查看**，切换入口有两处（联动同一状态）：

- 左侧栏「当前门店范围」下拉框
- 顶部标题栏右侧的下拉框

选项为「全部门店」或某一家分店（总店 / 静安店 / 浦东店）。切换后总览、看板等页面数据会实时重绘。

**左侧菜单分组：**

| 分组 | 页面 |
|---|---|
| 工作台 | 总览驾驶舱 |
| 店铺管理 | 店铺业绩看板、每日对账录入、门店档案 |
| 境外投流 | 境外推广看板、AI 客服接待、投流账户管理 |
| 自媒体 AI | 自媒体工作台、素材生成工坊 |
| 系统设置 | 权限管理、系统设置、AI 模型与密钥、小程序预览 |

> 菜单按角色权限显示：员工/店长看不到「系统设置」等无权限页面。侧栏底部显示版本号、版本类型和作者。

- **AI 经营解读**：点击右侧滑出抽屉，显示经营摘要与建议，点「知道了」关闭。

## 4. 店铺管理

### 4.1 店铺业绩看板（`/store`）
- 顶部切换「日 / 周 / 月」维度，指标随维度换算。
- 图表：营业额与耗卡趋势、项目营收占比、客户来源渠道。
- 门店对比区：下拉切换对比指标（总营业额 / 耗卡金额 / 充值金额 / 到店人次）。
- **AI 对账核对**：点开抽屉，基于对账记录显示核对结论；点「确认写入飞书」时，若未配置飞书凭证会提示去「系统设置」配置，配好后真实写入。

### 4.2 每日对账录入（`/reconcile`）
标准流程：**交给 Agent 核对 → 人工确认 → 写入飞书「门店每日台账」+ 本地留痕**。

**对账子表**：默认自动匹配该店多维表格里名为「**门店每日台账**」的子表；也可在
「系统设置 → 门店表格绑定 → 对账子表（门店每日台账）」里手动指定某个子表。系统的读取和写回都走这张表。

1. 选「对账日期」，确认页头当前门店正确。
2. 左侧是 **Agent 对话窗口**：
   - 直接**粘贴收银系统对账文本**，或点「上传文本/截图」上传 `.txt/.csv/.md` 文本文件；图片模型暂不识别图中文字，请补充粘贴金额文本。
   - 点「发送给 Agent」（Enter 也可发送），Agent 会调用管理员在「AI 模型与密钥 → Agent Skill 提示词 → 对账核对」里统一配置的 Skill 来解析内容。
   - 可连续追问；处理台账时 Agent 会在回答末尾给出 JSON 字段块，系统自动解析成可写入台账的字段。
   - **兼作 AI 助理**：同一个窗口也可以直接问经营分析、活动文案、客服话术、平台规则等问题，Agent 会以资深连锁运营顾问的口吻回答；这类普通问答**不会**输出台账字段，也不会写入表格。
3. 右侧「核对结果」显示识别出的字段；核对无误后点「**确认并写入台账**」。
4. 系统会同时：
   - 把识别字段写入飞书「门店每日台账」；
   - 在本地 MySQL 保存一条对账留痕（含飞书同步状态）。
   若飞书写入失败，本地记录仍会保存并标注「飞书同步失败」，可检查凭证/协作者权限后重试。
5. 下方两个表分别显示**飞书台账记录**（直接读自多维表格）和**本地对账留痕**；点「读取台账」可手动刷新。

### 4.3 门店档案（`/storefile`)
- 门店卡片：可「编辑」「员工管理」。
- 项目价目表：项目名称 / 类别 / 售价 / 耗卡价 / 时长 / 状态，可「新增项目」。
- 页头「新增门店」添加分店。

## 5. 境外投流

### 5.1 境外推广看板（`/ads`)
- 切换平台「Meta / Google Ads」，数据随之重绘。
- 指标：投流花费、曝光量、点击率 CTR、转化 / ROAS。
- 图表：花费与转化趋势、投放国家表现、转化漏斗。
- **AI 分析**：抽屉列出异常与优化建议。

**Meta 数据接入（两种方式，数据按汇率换算成人民币）**：
1. **官方 API 同步（推荐）**：先在「系统设置 → Meta 投流」配置长期 Token、广告账户 ID、汇率（见 7.4.2），然后点页头「**从 Meta 同步**」。系统通过 Graph API 按天拉取近 30 天 insights（花费/曝光/覆盖/点击/转化/国家），按日期写入看板；同一天重复同步会覆盖更新，不会重复计数。
   - 同步失败时按提示检查 Token 权限（`ads_read`）、广告账户是否已授权给系统用户。
   - **测试连接正常但看板仍无数据**：点页头「**诊断 Meta**」。该按钮会直接请求 Graph API 的原始响应并把结果展开显示（Token 已打码），分别列出「账户信息 / 最简 insights / 按天基础字段 / 按天含 reach+actions」四种请求的状态码、返回行数、原始错误码与 trace。据此可判断：
     - 账户信息成功、insights 返回 `0 行` → 该时间段账户确实无消耗，或日期范围不对；换时间段重试。
     - insights 报错含 `(#10)` / `permission` → 广告账户未授权给系统用户，或 `ads_read` 未生效（回到 7.4.2 补做「分配广告账户」）。
     - insights 报错含 `Unknown fields` / `(#100)` → 字段与当前 API 版本不兼容，把报错原文发给管理员。
     - 全部请求都超时/失败 → 服务器到 `graph.facebook.com` 的网络或代理问题。
   - 系统使用 Graph API **v24.0**。若 Meta 后续升级版本导致字段变化，以诊断结果为准调整。
   - **同步提示"新增 N 天"成功、但看板仍显示"暂无数据"**：这是旧版本（v1.4.4 及以前）的数据读取 bug——后端把存 JSON 的 `payload` 字段当字符串原样返回，前端按对象读取，导致所有行被过滤掉。v1.4.5 已在后端出口和前端入口双重修复；升级到最新版并强刷（Ctrl+F5）后即可正常显示。**历史已同步的数据无需重新拉取**，升级后会自动正确解析。
2. **CSV 导入（无需 Token）**：在 Ads Manager 导出报表 CSV，点页头「导入 CSV」→ 选文件或直接粘贴表格内容 → 导入。需含「日期」和「花费」列，支持英文/中文表头，按日期聚合。
3. **手动录入**：点「+ 录入数据」逐日填写，适合临时补录。

字段映射：Meta 的 `spend / impressions / reach / clicks / actions` 分别对应看板的花费、曝光、覆盖、点击、转化。

**转化口径（重要，v1.4.6 起）**：Meta 的 `actions` 里同时含真实转化（购买/线索/私信咨询）和大量互动噪音（帖子互动 `post_engagement`、视频播放 `video_view`、链接点击 `link_click` 等）。旧版本在识别不到预设事件时会把所有.action 相加，导致转化虚高十几倍、ROAS 失真。现版本规则：
- 优先用「系统设置 → Meta 投流」里指定的**转化事件**（精确匹配，或 `xxx.事件名` 后缀匹配）；
- 未指定时按优先级自动识别：**购买** → **线索** → **私信咨询**（`onsite_conversion.total_messaging_connection` 等，适合养生馆/本地生活）→ **注册**。同一组内多个重叠事件**只取最大值、不累加**（一次咨询会被记成多种 action_type），组间命中即止；
- 都识别不到则转化记 0，**绝不把互动/播放当转化**。
- 明细表新增「**转化口径**」列显示每天实际采用的事件；点「诊断 Meta」会直接列出各候选事件的数值，便于核对。国内以私信咨询为主的账户，转化数会明显小于旧版的虚高值，这是**正确修正**。
- 若你的实际转化事件不在自动识别范围内，在「Meta 投流 → 转化事件」填入该事件的准确名称（如 `onsite_conversion.total_messaging_connection`）后重新同步即可。

国家表现按国家维度的花费与转化计算。

## 7. 系统设置（重点，走真实后端）

### 7.1 飞书授权（标签页一）
> 飞书在本系统里是**业务数据库**：系统通过「企业自建应用」的 App ID / App Secret 调用飞书多维表格接口，把各店业务数据写进去。
> 注意：这不是「群机器人 / Webhook」。群机器人只能往群里发消息，**不能读写多维表格**，这里用不上。

**一、创建飞书应用（只做一次）**

1. 打开 <https://open.feishu.cn> → 开发者后台 → **创建企业自建应用**，名称如「鵲太醫数据同步」。
2. 进入应用 →「凭证与基础信息」，复制 **App ID**（`cli_` 开头）和 **App Secret**（通常只完整显示一次，妥善保存）。
3.「权限管理」→ 开通 **`bitable:app`（多维表格读写）**；如果只打算只读飞书数据，可只开 `bitable:app:readonly`。
4.「版本管理与发布」→ **创建版本并发布**。这一步很关键：不发布版本，权限不会生效（企业管理员可能需要审核）。

**二、在系统里填凭证**

1. 系统设置 →「飞书授权」→「+ 添加凭证」：
   - **App ID**：`cli_` 开头那串
   - **App Secret**：上一步复制的密钥
   - **范围**：`公司默认`（所有门店共用一把钥匙）或 `门店专用`（某家店单独一把）
2. 保存后列表里 Secret 只显示掩码；行内可「启用 / 停用」「编辑」「删除」。

**三、把应用加为表格协作者（每家店做一次）**

1. 打开该店的飞书多维表格 → 右上角「分享 / 添加文档应用」→ 搜索刚建的应用 → 赋予**可编辑**权限（只读降级则给「可阅读」）。
2. 复制该表格的 **app_token**：地址栏 `https://xxx.feishu.cn/base/bascnxxxx` 中 `bascn` 开头那一段（不要把整条链接填进去）。
3. 逐个打开子表，复制 **table_id**（URL 中 `?table=tblxxxx` 的参数）。
4. 到「门店表格绑定」标签页填 app_token、8 个子表 table_id，并选择使用哪把凭证。

**四、没配凭证 / 只读时会怎样**

- 本地 MySQL 功能（对账录入、门店档案、权限、看板、AI 客服本地数据等）**照常可用**；
- 需要写飞书的操作会明确提示「去系统设置配凭证」，不会假装成功；
- 若只给了只读权限，系统可读飞书但写入会被飞书拒绝，按**只读降级**使用。

**常见失败原因**

| 现象 | 原因 |
|---|---|
| 调接口报权限不足 | 应用没创建版本并发布 |
| 报 `no permission` / `not found` | 没把应用加为该多维表格的协作者 |
| 表格找不到 | app_token 填成了整条链接，应只填 `bascn` 开头那段 |
| 某个店写不进去 | 绑定时选的凭证与该表授权的应用不是同一个 |

### 7.2 门店表格绑定（标签页二）
> 每家门店一个飞书多维表格。

1. 点「+ 绑定门店」，选择门店，填写：
   - **多维表格 app_token**（`bascn` 开头）——**在哪里找**：在飞书里打开这家店的多维表格本身，看浏览器地址栏，形如
     `https://xxx.feishu.cn/base/bascnxxxxxxxxxxxx?table=tblxxxx&view=vewxxxx`
     其中 `/base/` 后面、`?` 之前的 **`bascn` 开头那一段**就是 app_token。**只填这一段，不要填整条链接，也不要带 `?table=...`。**
     - 如果地址栏是 `https://xxx.feishu.cn/wiki/...`（表格放在知识库里），点左侧该表格名称在新窗口打开，或点右上角「···」→「在新窗口打开」，地址就会变成 `/base/bascn...` 形式。
   - **表格链接**（可选，用于「打开表格」跳转）：这里才填完整 URL。
   - **使用凭证**：选 7.1 里添加的飞书应用凭证（公司默认或门店专用）。
   - **对账子表（门店每日台账）**：保存过一次绑定后，编辑时可从这里下拉选择该 base 下的子表；**留空会自动匹配名为「门店每日台账」的子表**。每日对账的读取与写回都走这张表。
   - **8 个子表的 table_id**：逐个打开左侧子表，地址栏 `?table=tblxxxx` 里的 `tblxxxx` 就是 table_id。对应：每日业绩、投流洞察、客服知识库、AI 回复、待人工接待、自媒体、素材、推送配置。
2. 保存后行内可「编辑」「打开表格」「解绑」（解绑不删数据，数据仍在飞书）。
> 前提：7.1 建的应用必须已被添加为该多维表格的协作者，否则即使 app_token 填对也会报无权限。

- 显示当前版本、本地提交、远程最新提交；有新版本时显示「● 有新版本」。
- 点「一键升级到最新版」→ 确认后自动拉代码、重建、重启，实时显示进度与日志。
- 完成后按 Ctrl+F5 强刷浏览器。**首次使用需先按 `docs/后台一键升级.md` 重跑一次部署脚本安装升级组件**，之后日常升级都在这里点即可，不用登录服务器。

**⚠️ 点「一键升级」提示 `Internal server error`（500）怎么办？**

原因：升级脚本以 root 运行，旧版本写完状态文件后没把文件属主改回运行用户（www/qty），导致下次后端（www）写状态时权限不足而报 500。v1.4.4 已修复。**在服务器执行下面这条命令即可当场解除，然后回后台重新点升级**（脚本会在升级过程中自我更新，以后不会再犯）：

```bash
sudo bash -c '
APP=/www/wwwroot/quetaiyiai-src        # 若改过源码目录，这里换成你的实际路径
RUN=www                               # 非宝塔环境通常是 qty，可用 ps -eo user,cmd | grep qty-api 确认
chown "$RUN:$RUN" "$APP/api/data/upgrade-status.json" "$APP/api/data/upgrade.log" 2>/dev/null
# 把升级器覆盖为最新版本（含自我更新与属主修复），避免下次升级又用旧脚本
curl -fsSL https://raw.githubusercontent.com/Evan78s/Qty_ai_conter/master/scripts/upgrade-runner.sh -o /tmp/qty-upgrade.sh \
  && install -m 750 -o root -g root /tmp/qty-upgrade.sh /usr/local/bin/qty-upgrade
echo "已修复，请回后台重新点一键升级"
'
```

说明：若连「检查更新/状态」都一直转圈，多半是 `.git` 被 root 拉取后属主异常，同一条命令里再补一句 `chown -R "$RUN:$RUN" "$APP/.git"`。执行后刷新设置页即可正常显示版本与新版本提示。

### 7.4.2 Meta 投流（标签页，仅总管理员可改）
用于让「境外推广看板」自动拉取 Meta 广告数据。

1. **在 Meta 后台准备凭证**（约 5 分钟）
   - 第一步：打开 `developers.facebook.com` → 我的应用 → 创建应用（普通/商务类型均可）。创建后在左侧「用例」里选「**用市场营销 API 创建并管理广告**」，按提示勾选 `ads_read` 权限并保存。你截图里的「应用定制和要求」出现绿色勾即表示这一步已完成。
   - 第二步：打开 `business.facebook.com` → 右上角齿轮「商务设置」→ 用户 → **系统用户** → 添加，创建一个系统用户（名字随意，如 `quetai-sync`）。
   - 第三步（关键，先做）：把应用分配给这个系统用户。左侧「账户 → 应用」确认你建的应用在列表里，不在就「添加 → 添加自己的应用」纳入；然后左侧「用户 → 系统用户」→ 点开该系统用户 →「资产 (Assets)」→「应用 (Apps)」→「添加」→ 勾选该应用 → 角色选「管理员/开发者」→ 保存。**不做这步，生成令牌时会报「没有可用权限」。**
     - **新版商务管理平台（右侧只有「已分配的资产 / 已安装应用」标签，没有「资产」区块）**：改从应用侧反向分配——左侧「账户 → 应用」→ 点开该应用 →「用户 (Users)」/「系统用户」→「添加」→ 选中该系统用户 → 角色选「管理员」→ 保存。效果完全相同。若右侧面板显示不全，先把浏览器窗口最大化（F11）再操作。
   - 第四步：在同一系统用户页 →「资产 (Assets)」→「广告账户 (Ad Accounts)」→「添加」→ 选中要同步的广告账户（ID 就是 Ads Manager 地址栏 `act=` 后面那串数字，如 `2041926046723925`）→ 权限选「**查看/读取 (View/Read)**」→ 添加。
   - 第五步：回到该系统用户详情页 → 点「**生成新令牌 (Generate new token)**」→ 应用选上面那个 → 到期日选「**永不过期 (Never expires)**」→ 分配权限里勾选 **`ads_read`**（此时应已出现）→ 点「生成令牌」→ **立即复制**长期 Access Token（`EAA` 开头，只显示一次）。
   - 关于截图里的「**发布 未发布**」和「成为技术提供方」：读取**自己公司**的广告账户不需要发布应用，也不需要成为技术提供方（那是给第三方服务商访问他人数据用的），保持未发布即可。只有后面要读取其他广告主的账户时才需要走发布/审核。
   - 常见困惑：点左侧「用例」里的「添加更多用例」弹窗时，找不到 `ads_read` 是正常的——**`ads_read` 是权限名，不是用例、也不是应用，不需要在这里创建**。这个弹窗只列出**尚未添加**的用例，已经加过的（如「用市场营销 API 创建并管理广告」）不会再显示；面板上该项的绿色勾就是已添加的标志。弹窗里那个「用 Meta 广告管理工具创建并管理应用广告」虽然名字相近，但明确写着「不包含市场营销 API 的访问权限」，**不要勾选**。`ads_read` 权限是在第三步「生成令牌」时勾选的。
   - 生成令牌走到「分配权限」时提示「**没有可用权限 / 将应用身份分配给系统用户或选择其他应用**」：说明选中的应用还没分配给这个系统用户，按下面顺序处理后再回到生成令牌：
     1. 左侧「账户 → 应用」看应用是否在列表里。不在则点「添加」→「添加自己的应用」→ 选中开发者后台建的应用 → 添加，把它纳入当前商务。
     2. 左侧「用户 → 系统用户」→ 点开该系统用户 →「资产」→「应用」→「添加」→ 勾选刚纳入的应用 → 赋予一个角色（如管理员/开发者）→ 保存。（也可反向操作：在「账户 → 应用」里点该应用 →「用户」→ 添加该系统用户。）
     3. 回到系统用户 → 重新「生成口令」→ 选应用 → 设到期日（长期用建议选"永不过期"）→ 此时「分配权限」里应出现 `ads_read`，勾选后生成。
     4. 若仍无权限：回开发者后台检查该应用的「用市场营销 API 创建并管理广告」用例是否已保存、顶部「必要操作」的红点提示是否处理完；仍不行再按 Meta 提示发布应用。
   - 判断配置是否已就绪：开发者后台 → 我的应用 → 左侧「用例」→「创建和管理广告」→「权限和功能」，列表里能看到 `ads_read` 即表示已挂到应用上。状态「准备测试」在开发模式下读取**自己公司**广告账户足够用，无需提交应用审核；「API 调用 0」只是还没有调用记录。这里没挂权限，生成令牌时自然也没有可选项。
2. **在本页填写**
   - **Access Token**：粘贴上面的长期令牌（提交后只显示掩码，加密存服务器）。
   - **广告账户 ID**：`act=` 后的纯数字，如 `2041926046723925`。
   - **商务管理 ID**：URL 里 `business_id=` 后的数字，如 `944158525162622`（备查，非必需）。
   - **汇率**：美元→人民币，默认 7.2，用于把 Meta 花费换算成看板显示的 ¥。
   - **转化事件**：如 `purchase`、`lead`、`onsite_conversion.total_messaging_connection`（私信咨询）；留空则按「购买→线索→私信咨询→注册」自动识别（见 7.4.3 转化口径说明）。改完需重新同步才会按新口径重算。
3. 点「保存配置」→「测试连接」，显示账户名与币种即成功。之后到境外推广看板点「从 Meta 同步」。

> 说明：Ads Manager 页面本身需登录且动态渲染，服务器无法直接抓取；系统走官方 Graph API 读取同一批数据，更稳定合规。没有 Token 时仍可用看板里的 CSV 导入。

### 7.5 权限管理（`/permission`)
- **新增用户**：填姓名、账号、角色（总管理员 / 店长 / 员工 / 只读审计）、可访问门店（多选）。
- **角色权限矩阵**：V 查看 / E 编辑 / A 审批 / X 导出，单元格可点切换。
- **门店管理**：添加门店、查看地址/店长/员工数。
- **审计日志**：操作记录，可「导出」。

### 7.6 AI 模型与密钥（`/aiconfig`）
> 所有 AI 调用都走**后端代理**：API Key 只保存在服务器并做 AES-256-GCM 加密，前端只能看到掩码，密钥不会下发到浏览器。系统支持任何 **OpenAI Chat Completions 兼容**接口。
> 「自媒体 AI 助手」对话框固定走**全局默认模型**（不使用个人 Key），所以全局没配 Key 时该对话框不可用。

**一、准备 Key**

先到供应商控制台拿到三样东西：**API Key**、**接口基地址（baseUrl）**、**模型名**。

| 供应商 | baseUrl 填什么 | 常用模型名 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat`、`deepseek-reasoner` |
| 阿里百炼（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`、`qwen-max` |
| 火山方舟 Ark 按量 | `https://ark.cn-beijing.volces.com/api/v3` | 你在方舟创建的接入点 ID（`ep-` 开头）或模型名 |
| 方舟 Agent Plan / 自定义 | 服务商提供的兼容接口地址 | 以服务商控制台显示为准 |

> 系统会在 baseUrl 后自动拼 `/chat/completions`；如果你填的地址本身已以 `/chat/completions` 结尾也能识别。不要带多余斜杠或查询参数。

**二、配置全局默认（仅总管理员）**

1. 进入「AI 模型与密钥」→ 在「全局 API Key」区填 **API Key、baseUrl、默认模型** → 保存。
2. 在「供应商接入」里可分别配置 DeepSeek / 方舟 / 百炼 / 自定义，并把其中一个设为默认。
3. 点对应供应商的「**测试连接**」：返回成功才说明 Key、地址和模型都可用；失败会显示供应商的原始报错，照着排查即可。

**三、个人自带 Key**

员工可在「我的 API Key」填自己的 Key（同样填 baseUrl 和模型）。留空则自动使用全局 Key。
优先级：**个人 Key > 场景绑定 > 全局 Key**。

**四、场景模型绑定**

5 个场景：**对账、投流、自媒体、客服、视频**。每个场景都能单独「修改」使用的模型与温度（temperature）：
- 对账、客服建议用较低温度（如 0～0.3），结果稳定；
- 自媒体、素材创意可用较高温度（如 0.7～1.0）。

场景模型会覆盖全局默认模型；某场景没单独指定时，才用全局默认。

**Agent Skill 在哪里安装 / 配置**：Skill **不是需要安装的插件**，就是后台的一段系统提示词，保存在「AI 模型与密钥 → Agent Skill 提示词」里。

1. 进入 **系统设置 → AI 模型与密钥 → Agent Skill 提示词**。
2. 场景选「**对账核对**」（这是「每日对账录入」Agent 使用的 Skill）。
3. 点「**套用默认 Skill 模板**」，系统会自动填入官方模板：**对账核对为主 + AI 运营助理为辅**的双能力提示词。
4. 点「**保存提示词**」即可对全公司生效，无需改代码、无需重启；留空则运行系统内置默认提示词。

模板要点：处理对账数据时只使用用户提供信息、不编造数字、末尾输出 JSON 字段块；处理其他运营问题时直接给出专业建议、不输出 JSON。管理员可以直接编辑这段提示词，调整字段口径、语气或增加行业规则。

**五、常见失败原因**

| 现象 | 原因 / 处理 |
|---|---|
| 提示「尚未配置 AI Key」 | 全局和个人都没填 Key，先去本页配置 |
| 测试连接报 401 / invalid key | Key 填错、已过期或被删除 |
| 报 404 | baseUrl 填错；确认是 OpenAI 兼容根地址（含或不含 `/v1` 按服务商要求） |
| 报 model not found | 模型名不一致；DeepSeek 用 `deepseek-chat`，方舟用 `ep-` 接入点，百炼用 `qwen-*` |
| 报权限 / 白名单错误 | 把服务器出口 IP 加入供应商白名单，或检查账号是否开通对应模型 |
| 报余额不足 / 限流 | 到供应商控制台充值或降频；测试连接会显示原始错误 |
| 前端看不到 Key | 正常现象：加密存服务器，前端只显示掩码 |

## 9. 数据说明：什么存本地、什么需要配凭证

系统所有按钮均已接入真实逻辑，不再有「点击只弹演示提示」的占位按钮。数据分两类：

### ✅ 本地型（存 MySQL，打开就能用，无需任何外部账号）
所有增删改查都写进你自己的数据库，刷新页面数据还在：

| 模块 | 真实能力 |
|---|---|
| 登录 / 改密 / 退出 | MySQL 校验，首次登录强制改密 |
| 系统初始化 `/setup` | 建表 + 建管理员 + 自动生成密钥 |
| 门店档案 | 新增 / 编辑 / 删除门店，新增 / 编辑 / 删除价目表 |
| 用户与权限 | 用户增删改（含改密、角色、可访问门店）、角色权限矩阵编辑、审计日志导出 |
| 每日对账 | 录入对账文本 / 截图、AI 核对、确认记录，全部落库 |
| AI 模型与密钥 | 全局 / 个人 Key 加密保存、场景绑定、测试连接 |
| AI 客服 | 知识库增删改、待接待队列、回复记录、推送配置均落库 |
| 素材工坊 | AI 生成文案 / 脚本（需 Key）、素材库保存与删除 |
| 自媒体 | 账号、发布计划、互动回复本地保存，发布日历按真实计划渲染 |
| 境外投流 | 每日投流数据录入，KPI / 图表 / 漏斗按真实录入数据计算 |
| 总览 / 业绩看板 | 指标、门店排行从对账记录真实汇总，无记录时显示 0 并提示去录入 |

### ⚙️ 外部型（需先配凭证，否则会明确提示去哪配，不再假装成功）
以下功能依赖第三方账号，系统已写好真实调用代码，但**必须先在对应页面配置好凭证**才能真正跑通：

| 功能 | 需要先配置 | 配置位置 |
|---|---|---|
| AI 生成内容 / AI 解读 / AI 核对 | 自己的 AI Key（DeepSeek / 方舟 / 阿里百炼等） | 侧栏「AI 模型与密钥」 |
| 写入飞书多维表格 / 飞书群推送 | 飞书应用凭证 + 每店表格绑定 | 侧栏「系统设置」 |
| Meta / Google 投流数据自动拉取 | 投流账户授权（OAuth） | 侧栏「系统设置 → 集成」 |

> 没配凭证时点击这些按钮，会弹出「请先到 XX 页配置」的明确引导，而不是弹「演示」。配好后即为真实调用。小程序页面为产品形态预览示意，不包含独立后端。

## 10. 常见问题

| 问题 | 处理 |
|---|---|
| 打不开网页 | 确认域名解析、宝塔站点与 SSL 正常；后端 `systemctl status qty-api` 应为 active |
| `/setup` 或子页面 404 | 宝塔「网站 → 设置 → URL 重写 / 伪静态」填 `try_files $uri $uri/ /index.html;` |
| 测试连接 502 | 后端没起来：查 3000（或你改的端口）是否被占用、Nginx 反代端口是否与后端一致 |
| 忘记管理员密码 | 进数据库 `quetaiyiai` 的 `users` 表重置（密码为 bcrypt+pepper，建议重装初始化或联系维护者） |
| 飞书写入失败 | 检查凭证是否有效、`bitable:app` 权限是否开通、应用是否为表格协作者、8 个 table_id 是否填对 |
| 页面数据不刷新 | Ctrl+F5 强刷；PWA 已禁用数据缓存，每次打开取最新版 |
| 想升级到最新版 | 网站目录版：`cd /www/wwwroot/quetaiyiai-src && git pull && bash scripts/web-deploy.sh` |
