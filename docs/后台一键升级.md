# 后台一键升级（系统设置内）

鵲太醫 AI 运营工作台（连锁店版）支持在**网页后台 → 系统设置 → 系统升级**里一键把系统升到 GitHub 上的最新版本，无需登录服务器敲命令。

## 一、启用前：先安装一次升级组件（只需做一次）

后台一键升级需要服务器上有「升级执行器」和 sudo 白名单，它们由部署脚本安装。**如果你之前已经用网站目录部署脚本装过系统**，重新跑一次脚本即可补装升级组件（不会动你的数据库和已装代码之外的东西）：

```bash
curl -fsSL https://raw.githubusercontent.com/Evan78s/Qty_ai_conter/master/scripts/web-deploy.sh -o /tmp/qty-web-deploy.sh && sudo QTY_API_PORT=3100 bash /tmp/qty-web-deploy.sh
```

> 端口换成你实际的后端端口（例子里是 3100；若没改过就用默认，去掉 `QTY_API_PORT=3100`）。
> 脚本会自动：`git pull` 到最新 → 安装 `/usr/local/bin/qty-upgrade` → 配置 sudo 免密白名单（仅允许运行用户执行这一个固定脚本）→ 重建并重启服务。

跑完后到后台「系统设置 → 系统升级」，看到「组件状态：● 已是最新 / ● 有新版本」就说明升级组件已就绪。

## 二、日常升级（以后每次都这样做）

1. 登录后台 → **系统设置** → **系统升级**。
2. 页面显示当前版本、本地提交号、远程最新提交号：
   - 显示「● 有新版本」→ 点「一键升级到最新版」。
   - 显示「● 已是最新」但仍想重装 → 点「重新拉取并升级」。
3. 确认弹窗后，系统自动拉代码、重建前后端、重启服务，页面会**实时显示进度**（拉取代码 → 构建前端 → 构建后端 → 发布前端 → 重启服务 → 完成）。
4. 看到「升级完成」后，按 **Ctrl+F5** 强刷浏览器加载新版前端。

整个过程约 1 分钟，期间网站会短暂无法访问（服务重启），**数据不会丢失**。

> 只有**公司总管理员**能看到并点击升级按钮；店长、员工、审计角色看不到。

## 三、怎么看状态和日志

- 页面顶部四个状态框：当前版本、本地提交、远程最新、组件状态。
- 「刷新状态」：手动拉取最新升级状态（升级时一般自动轮询）。
- 「查看日志」：显示升级执行日志（`api/data/upgrade.log` 末尾 200 行），构建失败时在这里看原因。
- 若升级失败，页内会红框提示，并保留错误信息。

## 四、安全说明

后台能触发升级，但权限被严格限制：

- 网页接口只接受**公司总管理员**，且需要系统编辑权限。
- 后端以普通用户（www/qty）运行，本身无权改源码、无权重启服务。
- 真正的升级动作通过 sudo 白名单交给一个**路径固定、不接受任何参数**的 root 脚本执行，普通用户无法借此运行任意命令。
- 升级脚本用文件锁防止并发，重复点击不会重复执行。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 页面显示「当前部署方式不支持在线升级」 | 先按第一节重跑部署脚本安装升级组件 |
| 点升级提示「服务器未安装升级组件」 | 同上，且需确认后端已重启（新接口生效） |
| 升级卡在「拉取代码」并失败 | 看日志；多为服务器无法访问 GitHub 或本地有改动冲突，可 `cd 源码目录 && git status` 检查 |
| 升级失败后网站打不开 | 用命令行恢复：`cd /www/wwwroot/quetaiyiai-src && sudo QTY_API_PORT=3100 bash scripts/web-deploy.sh` |
| 升级完成但页面还是旧的 | Ctrl+F5 强刷；仍不行则清浏览器缓存（PWA 可在开发者工具里清 Storage） |
| Docker 部署的用户 | 在线升级目前仅支持「网站目录部署」方式；Docker 请用 `docker compose pull && docker compose up -d --build` 或重跑 boot.sh |

## 六、升级命令速查（备用）

```bash
# 网站目录版手动升级（与后台一键升级等价）
curl -fsSL https://raw.githubusercontent.com/Evan78s/Qty_ai_conter/master/scripts/web-deploy.sh -o /tmp/qty-web-deploy.sh && sudo QTY_API_PORT=3100 bash /tmp/qty-web-deploy.sh

# 查看升级日志
tail -100 /www/wwwroot/quetaiyiai-src/api/data/upgrade.log

# 查看升级状态
cat /www/wwwroot/quetaiyiai-src/api/data/upgrade-status.json
```
