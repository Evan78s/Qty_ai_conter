# 养元汇 AI 运营工作台 · 部署与运维手册（Linux / v5 单公司版）

> 适用：自有 Linux 服务器 + 公网 IP + 已解析域名。全程自建，不依赖任何云端数据库服务。
>
> **v5 数据架构（重要）**：
> - **部署模型**：一套系统 = 一家公司 = 一个独立 MySQL 数据库，管理这家公司的所有分店。别家公司下载同样的系统各自部署、各自接自己的库，多套互不干扰。**无"租户管理"层**。
> - **MySQL = 系统库**：账号/角色/权限/会话/飞书凭证/品牌设置/审计/同步映射（tenants 表仅内部占位保留）
> - **飞书 = 业务库**：业绩、投流、知识库、AI 回复等业务数据全部存飞书表格/文档，本地不留副本（仅同步映射表存只读降级快照）
> - 角色两级：公司总管理员 → 店长/员工/审计；门店数据按授权范围隔离

---

## 0. 部署前清单

- [ ] Linux 服务器一台（建议 2vCPU / 4G / 40G SSD），已完成初始化与安全加固
- [ ] 域名已解析到该服务器，80/443 端口可从公网访问（certbot 申请证书需要）
- [ ] 已安装 MySQL 8.0（见第 1 步），并建好数据库与账号
- [ ] 具备 sudo/root 权限
- [ ] 已备好随机密钥（见第 2 步）
- [ ] （阶段 4 起）飞书自建应用 app_id/app_secret，具备多维表格与文档权限

## 1. 环境初始化（一次性）

```bash
# 安装 Node.js LTS（22 或 24）、Nginx、certbot、MySQL 8、防火墙
sudo apt update && sudo apt install -y nodejs npm nginx certbot python3-certbot-nginx mysql-server ufw
# 若系统 Node 版本过低，用 n 或 NodeSource 升级到 22/24 LTS

# 初始化 MySQL 安全配置
sudo mysql_secure_installation

# 创建数据库与专用账号（替换密码）
sudo mysql -u root -p <<'SQL'
CREATE DATABASE yangyuanhui CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'yyh'@'127.0.0.1' IDENTIFIED BY '替换为强密码';
GRANT ALL PRIVILEGES ON yangyuanhui.* TO 'yyh'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL

# 创建运行用户（API 以非 root 运行）
sudo useradd -r -m -s /usr/sbin/nologin yyh

# 防火墙：只放行 SSH / HTTP / HTTPS（MySQL 仅本机访问，不对外开放 3306）
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
```

SSH 加固：改用密钥登录、禁用 root 直登、安装 fail2ban（暴破防护）。
**MySQL 只监听 127.0.0.1**，绝不暴露 3306 到公网。

## 2. 生成密钥

```bash
# 三个密钥各生成一次，妥善保存（丢失会导致加密数据不可解）
openssl rand -hex 32   # JWT_SECRET
openssl rand -hex 32   # KEY_ENCRYPTION_KEY
openssl rand -hex 24   # PASSWORD_PEPPER
```

## 3. 配置环境变量

```bash
sudo mkdir -p /opt/yangyuanhui/api
sudo cp <源码>/api/.env.example /opt/yangyuanhui/api/.env
sudo nano /opt/yangyuanhui/api/.env
```
填入上一步生成的密钥，并设置：
```env
NODE_ENV=production
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=yyh
DB_PASSWORD=第1步设置的数据库密码
DB_NAME=yangyuanhui
DOMAIN=你的域名
```
```bash
sudo chmod 600 /opt/yangyuanhui/api/.env
sudo chown yyh:yyh /opt/yangyuanhui/api/.env
```

## 4. 部署应用

```bash
# 将本地源码目录上传到服务器（如 /srv/yangyuanhui-src），然后：
sudo bash /srv/yangyuanhui-src/scripts/deploy.sh
```
脚本会：构建前后端 → 创建目录与用户 → 发布产物 → 建 MySQL 表 → 种子数据（公司占位 + 4 角色 + 3 门店 + 5 AI 场景 + 品牌设置）。

**从旧 SQLite 系统迁移**（仅首次升级需要）：先在运行 deploy.sh 前，把旧 `app.db` 放到服务器，配置 `.env` 后执行：
```bash
cd /opt/yangyuanhui/api
ETL_SQLITE_PATH=/path/to/old/app.db node -e "require('./dist/scripts/etl-sqlite-to-mysql.js')"
# 账号密码原样迁移；全员需重新登录；业务数据无需迁移（已在飞书）
```

## 5. 创建平台总管理员

```bash
sudo bash /opt/yangyuanhui/scripts/bootstrap-admin.sh admin
```
**随机初始密码只打印一次**，请立即保存。首次登录会强制改密。公司总管理员可管理本公司所有分店与全局设置。

## 6. 配置 systemd 与 Nginx

```bash
# systemd
sudo cp <源码>/deploy/yangyuanhui.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now yangyuanhui
sudo journalctl -u yangyuanhui -f      # 查看日志

# Nginx（替换 your-domain.com）
sudo cp <源码>/deploy/nginx.conf /etc/nginx/sites-available/yyh
sudo sed -i 's/your-domain.com/你的域名/g' /etc/nginx/sites-available/yyh
sudo ln -s /etc/nginx/sites-available/yyh /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# HTTPS 证书（自动申请 + 配置）
sudo certbot --nginx -d 你的域名
sudo certbot renew --dry-run            # 验证自动续期
```
> 阶段 6 品牌配置上线后，Nginx 需增加 `/uploads/` 静态别名指向 `/opt/yangyuanhui/data/uploads`，用于 logo 图片。

浏览器访问 `https://你的域名` 即可登录。

## 7. 日常运维

| 事项 | 命令 / 方式 |
|---|---|
| 查看服务状态 | `systemctl status yangyuanhui` |
| 查看日志 | `journalctl -u yangyuanhui -f` |
| 重启服务 | `sudo systemctl restart yangyuanhui` |
| 健康检查 | `curl https://你的域名/api/health`（返回 `db:"ok"` 表示 MySQL 连通） |
| 手动备份 | `sudo bash /opt/yangyuanhui/scripts/backup.sh` |
| 恢复备份 | `sudo bash /opt/yangyuanhui/scripts/restore.sh db_日期.sql.gz` |
| MySQL 状态 | `mysqladmin -u yyh -p status` |
| 证书续期 | certbot systemd timer 自动，月度 `certbot renew --dry-run` 验证 |

**自动备份**：加入 crontab，每天凌晨 2 点执行：
```bash
0 2 * * * bash /opt/yangyuanhui/scripts/backup.sh
```

## 8. 备份策略（关键）

- 每日 `mysqldump --single-transaction` 在线备份系统库，保留 30 天；周日备份留 3 个月
- **`.env`（含主密钥）与证书一并备份**——主密钥丢失会导致所有加密的飞书凭证/API Key 不可解（不可逆）
- 品牌 logo 上传目录 `data/uploads/` 一并备份
- 强烈建议异地副本：`rsync` 推到另一台机器或 NAS
- 每季度演练恢复：`restore.sh` 恢复到库，执行 `CHECK TABLE` 确认无损坏
- **业务数据在飞书**，其可用性由飞书保障；本地同步映射表仅作降级快照

## 9. 安全清单

- [ ] 系统 / Node / Nginx / MySQL / npm 依赖定期更新
- [ ] SSH 密钥登录、禁 root、fail2ban、ufw 仅放行 22/80/443
- [ ] MySQL 仅监听 127.0.0.1，专用账号最小权限，绝不用 root 连接应用
- [ ] API 以 `yyh` 用户运行，`.env`/备份权限 600
- [ ] 全程 HTTPS，登录限流（5 次/15 分钟/IP）
- [ ] 任何密钥不进代码库、日志、URL
- [ ] 门店隔离：所有带 store_id 的查询经 scoped-repo 注入可见门店范围；新增接口须做越权测试（单公司部署，无租户维度）
- [ ] 可选：前置 Cloudflare 免费版隐藏源站 IP，抗 DDoS

## 10. 故障排查

| 现象 | 排查 |
|---|---|
| 打不开页面 | `nginx -t`、`systemctl status nginx`、检查域名解析与安全组 |
| 登录报 500 | `journalctl -u yangyuanhui -n 50`，检查 `.env` 的 DB_* 与密钥是否配置 |
| `/api/health` db:error | MySQL 未启动或凭据错误：`systemctl status mysql`、核对 `.env` 的 DB_USER/PASSWORD |
| 连接池耗尽 | 检查 `DB_POOL_LIMIT`、是否有慢查询：`SHOW PROCESSLIST` |
| HTTPS 证书错误 | `certbot certificates`、`certbot renew --dry-run` |
| 飞书写入失败 | 检查系统设置的授权状态、`sync_mappings.last_error`、飞书应用权限 |

## 11. 数据架构说明（v4）

- **系统库（MySQL）**：13 张表——tenants(内部占位)/roles/stores/users/user_stores/sessions/ai_configs/ai_scenes/integrations/platform_settings/store_feishu_bindings/sync_mappings/audit_logs/schema_migrations
- **业务库（飞书）**：业绩/投流/知识库/AI 回复等业务数据存飞书多维表格，工作台录入后写入飞书、展示时实时读回
- **同步映射**：`sync_mappings` 记录 `biz_key ↔ feishu_record_id`，保证幂等；`snapshot_json` 存最近一次读取结果，仅用于飞书故障时的只读降级
- **迁移**：旧 SQLite 系统库通过 `api/src/scripts/etl-sqlite-to-mysql.ts` 一次性迁移；不再迁 PostgreSQL（`scripts/migrate-pg.sh` 已废弃）
