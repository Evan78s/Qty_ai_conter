# 鵲太醫 AI 运营工作台（连锁店版）· 网站目录部署（宝塔面板）

> **不用 Docker**：前端构建后放进网站目录，后端用 systemd 守护，数据库用宝塔 MySQL，域名 / SSL 交给宝塔。
> 适合：已经在宝塔建好站点、希望「域名指向网站目录就能用」的场景。

---

## 先说清楚一点

这个系统不是纯静态网页：除了前端页面，还有一个 **Node.js 后端**（负责登录、权限、安装向导、飞书凭证加密）和一个 **MySQL 系统库**。所以不能像 WordPress 那样把文件丢进目录就完事。

但下面的脚本已经把麻烦的部分全做了：拉源码 → 构建前端 → 构建后端 → 把前端放进网站目录 → 启动后端服务。你**只需在宝塔面板点几下建库、加一段反代配置**，然后在网页安装向导里填数据库信息。

---

## 一键部署

在服务器复制这一行执行：

```bash
curl -fsSL https://raw.githubusercontent.com/Evan78s/Qty_ai_conter/master/scripts/web-deploy.sh -o /tmp/qty-web-deploy.sh && sudo bash /tmp/qty-web-deploy.sh
```

默认路径：

| 用途 | 路径 |
|---|---|
| 网站根目录（前端文件） | `/www/wwwroot/qtyai` |
| 源码与后端运行目录 | `/www/wwwroot/qtyai-src` |
| 后端监听 | `127.0.0.1:3000`（不对外，由 Nginx 反代） |

如果你的宝塔网站目录已经是域名（例如 `/www/wwwroot/guanli.你的域名.com`），指定它即可：

```bash
sudo QTY_WEB_ROOT=/www/wwwroot/guanli.你的域名.com bash /tmp/qty-web-deploy.sh
```

脚本会自动安装 Node.js 22（若系统已有 Node ≥ 20 则跳过），并把后端注册为 systemd 服务 `qty-api`，开机自启。

## 脚本跑完后，在宝塔做 3 件事

### 1️⃣ 建数据库

宝塔面板 → **数据库** → **添加数据库**：

- 数据库名：`yangyuanhui`
- 用户名：`qty`
- 密码：自己设一个强密码（**记下来**，下一步要用）
- 字符集：`utf8mb4`
- 访问权限：本地访问即可（不要开放外网）

**不用手动建表**，网页安装向导会建。

### 2️⃣ 加反向代理

宝塔面板 → **网站** → 你的域名 → **设置** → **配置文件**，在 `server { }` 里面加入：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 20m;
}
```

同一页面的 **伪静态** 填入（支持前端页面刷新不 404）：

```nginx
try_files $uri $uri/ /index.html;
```

> 脚本也会把这段配置写到 `/www/wwwroot/qtyai-src/nginx-snippet.conf`，可以直接复制过去改。

### 3️⃣ 网页安装向导

浏览器打开 `https://你的域名/setup`，填写：

| 字段 | 值 |
|---|---|
| 数据库地址 | `127.0.0.1` |
| 端口 | `3306` |
| 库名 | `yangyuanhui` |
| 用户名 / 密码 | 第 1 步建的 |
| 管理员账号 / 密码 | 自己设（密码 ≥ 8 位） |

点「测试连接」→「一键安装」。系统会自动建表、创建管理员，并**自动生成 JWT / 加密 / 加盐密钥**写入 `/www/wwwroot/qtyai-src/api/data/install.json`，无需手动生成 `.env` 密钥。

搞定后访问 `https://你的域名` 登录，首次会强制改密。

## 日常运维

```bash
systemctl status qty-api              # 后端状态
journalctl -u qty-api -f              # 实时日志
systemctl restart qty-api             # 重启后端
curl https://你的域名/api/health      # 健康检查（返回 db:"ok" 表示数据库连通）
```

### 升级到新版

```bash
cd /www/wwwroot/qtyai-src
git pull
bash scripts/web-deploy.sh
```

前端文件会覆盖到网站目录，后端会重新构建并重启。**数据库和 `install.json` 不受影响，数据不丢。**

> 若网站目录里放了其他自定义文件，升级前先备份；脚本只覆盖构建产物，不删除目录里的其他内容（旧版本的带 hash 的静态文件可能残留，不影响使用）。

## 和 Docker 版怎么选

| | Docker 一键部署 | 网站目录部署（本文） |
|---|---|---|
| 适合 | 全新服务器、想一条命令搞定 | 已有宝塔站点、想沿用域名/SSL/数据库管理 |
| 端口冲突 | 需避开 80（用 `HTTP_PORT=8080`） | 不占额外对外端口，用宝塔已有 80/443 |
| 数据库 | 容器内 MySQL（卷持久化） | 宝塔 MySQL |
| 升级 | `git pull` + `docker compose up -d --build` | `git pull` + `bash scripts/web-deploy.sh` |
| 数据迁移 | 两种方式的库**不通用** | 两种方式的库**不通用** |

> 如果 Docker 版已经跑通了，没必要切换；两种方式都需要各自在网页向导里初始化数据库。

## 常见问题

| 现象 | 排查 |
|---|---|
| 页面能开，登录/接口 404 | 宝塔没加 `/api/` 反代，或反代路径写错 |
| 刷新子页面 404 | 伪静态没配 `try_files $uri $uri/ /index.html;` |
| `/setup` 测试连接失败 | MySQL 是否只允许本地；库名/账号/密码是否正确；宝塔数据库是否启动 |
| 接口 500 | `journalctl -u qty-api -n 50` 看日志；通常是数据库权限或 `install.json` 权限问题 |
| `install.json` 找不到 | 默认在 `/www/wwwroot/qtyai-src/api/data/install.json`，**备份时务必包含它** |
| 升级后样式没更新 | 浏览器强刷（Ctrl+F5）；本系统 PWA 不缓存旧版 |
| 后端端口 3000 被占用 | `QTY_API_PORT=3001` 重新执行脚本，并把反代里的 `3000` 改成 `3001` |

---

## 安全提醒

- `install.json` 含 3 个主密钥，丢失后飞书凭证 / API Key 无法解开，**不可逆**，请纳入备份。
- MySQL 不要开放公网访问；后端只监听 `127.0.0.1`。
- 全站走 HTTPS（宝塔申请证书），PWA 安装到手机/电脑桌面需要 HTTPS。
